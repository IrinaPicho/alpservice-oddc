# Альпсервис — ОДДС

Один сайт + один сервер + одна база данных. Все файлы лежат в одной папке, без вложенных подпапок — это сделано специально, чтобы загрузка на GitHub через браузер (без командной строки) никогда не "ломала" структуру проекта.

## Что внутри

- `index.html`, `style.css`, `app.js`, `manifest.webmanifest`, `sw.js`, иконки — сам сайт (то, что видит пользователь).
- `server.js` — сервер. Отдаёт сайт и обрабатывает запросы к базе данных.
- `routes-auth.js`, `routes-reports.js`, `routes-accountants.js`, `routes-uploads.js`, `db.js`, `jwt.js` — части сервера.
- `schema.sql` — структура базы данных (таблицы). Нужно выполнить один раз при первом запуске.
- `update-1.sql` — добавляет в уже существующую базу то, что нужно для остатка (сальдо) и нумерации отчётов. Если база создавалась раньше (через `schema.sql` без этого файла) — выполнить один раз дополнительно, после `schema.sql`.
- `update-2.sql` — добавляет поля "Контрагент" (у отчета) и "Юридическое лицо" (у сотрудника), нужны для таблицы управленческого учета по шаблону клиента. Выполнить один раз, после `update-1.sql`.
- `ao1-template.xlsx` — официальный бланк АО-1 (прислан клиентом), сервер открывает именно этот файл и дописывает туда данные при каждой выгрузке — поэтому вид бланка всегда совпадает с официальным. Файл не трогаем руками, он используется кодом автоматически.
- `ao1.js` — часть сервера, которая заполняет бланк АО-1 данными сотрудника.
- `seed.js` — создаёт 3 демо-аккаунта (сотрудник / бухгалтер / руководитель) для проверки.
- `package.json` — список того, что нужно серверу для работы (устанавливается командой `npm install`, это делает хостинг сам).
- `.env.example` — образец настроек. На хостинге нужно будет указать свои значения (адрес базы данных и секретный ключ).

Папки `node_modules` и `uploads`, а также файл `.env` — не загружаем на GitHub. `node_modules` — это скачанные программой библиотеки (их хостинг сам установит), `uploads` — папка для загруженных чеков (создаётся сама), `.env` — файл с настоящими паролями (на хостинге их вводят в специальной форме, а не файлом).

## Как запустить на Railway

1. На Railway: New Project → Deploy from GitHub repo → выбрать этот репозиторий.
2. Add a plugin → PostgreSQL (создаст базу данных автоматически).
3. В настройках сервиса, в Variables, добавить:
   - `DATABASE_URL` — Railway подставит сам (ссылка на базу).
   - `JWT_SECRET` — любой длинный случайный набор букв и цифр.
   - `FRONTEND_ORIGIN` — адрес сайта на Railway (можно оставить пустым на первом шаге).
4. Один раз выполнить `schema.sql` на базе данных Railway (через вкладку базы данных → Query) — это создаёт таблицы.
5. Запустить `npm run seed`, чтобы появились демо-аккаунты (через вкладку сервиса → Shell, если она есть, либо через консоль Railway).
6. Railway выдаст адрес сайта (например `alpservice-oddc.up.railway.app`) — он сразу рабочий.
7. Позже на этот адрес можно подключить свой домен (в настройках сервиса → Settings → Domains).

На этой странице: один период (дата "с" и "по") на всех сверху, и список сотрудников проекта, у каждого — две кнопки. Кнопка "УО" (управленческий отчет) скачивает Excel ровно по шаблону клиента (9 колонок, те же названия и тот же порядок) за выбранный период, только по этому сотруднику и только по одобренным отчетам. Общей выгрузки сразу по всем сотрудникам нет — решили, что так проще.
- Можно нажимать Enter вместо клика по кнопке: при входе, при регистрации и при отправке отчета/прихода — если в этот момент курсор стоит в одном из полей формы, Enter делает то же, что и нажатие на основную кнопку.
- Кнопка "АО-1" на странице "Выгрузка отчетов" теперь активна и скачивает официальный унифицированный бланк АО-1 (точно тот же файл, что прислал клиент) — заполненный автоматически: сотрудник, его табельный номер и должность, проект, сумма выданного аванса и потраченного, и построчно каждая одобренная операция-расход за выбранный период (если операций больше 8 — бланк сам добавляет строки, не теряя ни одной). Для нового сотрудника обязательно укажите табельный номер при регистрации (новое поле в форме) — без него поле в бланке останется пустым, остальное всё равно заполнится.
  - Две вещи бланк не умеет заполнить сам, потому что их не знает ни один наш сайт, а только сама компания: код по ОКПО (строка "по ОКПО") и должность руководителя (строка "Руководитель") — в них стоит слово "ЗАПОЛНИТЬ", как было и в образце от клиента. Если скажете мне эти два значения — впишу их один раз в сам образец, и дальше они будут появляться на каждом бланке сами.
  - "Назначение аванса" заполняется фразой "Хозяйственные нужды" — если нужна другая формулировка, скажите, поменяю.
  - "Предыдущий аванс" (переходящий остаток с прошлого раза) бланк не считает — в приложении пока нет истории авансов по периодам, только текущая выданная сумма. Эту строку, если нужно, можно дописать от руки при печати.

## Если после обновления сайта ничего не изменилось

Сайт умеет работать как приложение (его можно "установить" на телефон) — для этого у него есть файл `sw.js`, который один раз сохраняет сайт на телефоне/в браузере, чтобы он открывался и без интернета. Проблема: он может сохранить версию сайта один раз и потом показывать именно её, даже когда на сервере уже лежит новая версия — то есть человек пользуется старой, сохранённой копией сайта, а не настоящей новой.

Именно это вызывало баг "нажимаю Обновить — выкидывает на вход": браузер показывал старую, сохранённую версию сайта (в которой ещё не было настоящего входа через сервер), а не ту, что только что обновили.

Исправление в этой версии: `sw.js` теперь всегда сначала пробует загрузить сайт с сервера (сохранённая копия — только на случай отсутствия интернета), и у сохранённой копии теперь есть "номер версии" (`CACHE_NAME`), который нужно менять при каждом следующем обновлении сайта — иначе эта же проблема может повториться. Я буду менять этот номер сама/сам при каждом следующем обновлении, которое отправлю.

Если у кого-то из сотрудников сайт всё равно продолжает выглядеть по-старому после того, как новая версия загружена на GitHub и Railway её развернул — нужно закрыть сайт/приложение полностью и открыть заново (на телефоне — смахнуть приложение из списка недавних и открыть заново; в браузере — закрыть вкладку и открыть сайт заново).
